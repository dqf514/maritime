MariOS 全流程操作手册

面向航运公司日常工作演练：从估算成交、航次执行、滞期索赔到财务结算与管理数据看板，并覆盖 AI 助手、邮件复核、例行任务中枢与事件自动化。本地演示入口 http://localhost:3000。

1. 当前系统可否用于全流程日常工作？

结论：可用于「试点 / PoC / 培训演练」级的全流程日常台面；尚不宜作为大型航运公司生产环境的唯一核心系统全面替代。

商业主干（估算 → 租约 → 航次 → 装卸时间/索赔 → 燃油 → 发票收付款）在产品台面与自动化测试中已打通； 邮件业务（复核 / AI 落地 / 业务草稿）、AI 助手与对话、事件驱动的任务自动化、例行任务中枢、单据 PDF 已接入日常台面（见第 6 节）。 ERP 深集成、船期甘特硬冲突、报表钻取仍偏演示或待加深。

估算 TCE→ 租约审批→ 航次执行→ SOF / 午报→ Laytime→ 索赔 / 发票→ 收付款 / GL→ 损益 / 数据看板

3. 商务全链路操作（租船视角）

登录并进入工作台

  1. 打开 /login，租户码 demo，使用租船账号登录。
  2. 进入 /home 工作台，确认角色快捷入口与小部件。

主数据确认

  1. 打开船舶 / 港口 / 对手方主数据页，确认有可用船舶、装卸港与租家。
  2. 若对手方制裁状态为 blocked，租约将无法激活（合规拦截）。

航次估算（Estimate）

  1. 进入 /estimates，新建估算：选择船舶、对手方，填写货量、运价/包干、佣金、航次天数、燃油与港口费等。
  2. 点击计算得到 TCE；可克隆方案做对比与敏感度。
  3. 已有邮件或聊天记录时，用「从文本填充」粘贴解析，逐字段核对后写入表单（见第 6 节）。
  4. 满意后执行转租约（To CP），生成草稿租约。

页面路径：/estimates

租约审批与激活

  1. 进入 /charters，打开由估算生成的租约。
  2. 状态流转：draft → pending_approval → active（不可跳过）。
  3. 激活后系统可关联生成航次（视种子与链路配置）。
  4. COA 场景可在租约台记录 lifting；租约修订获批会发出域事件，自动通知相关部门并派财务复核任务。

4. 航次运营（操作视角）

开航与挂靠港

  1. 使用操作账号登录，打开 /operations/voyages。
  2. 将航次状态切至进行中；新增装港 / 卸港挂靠（顺序、ETA、代理等）。
  3. 录入午报（船位、航速、ROB、下一港 ETA）；系统可提示 ETA 偏差。
  4. 在挂靠港下登记 SOF 事件（如 NOR），注意使用本地时区。
  5. 航次工作台的Closeout（收尾）页逐项核对：挂靠港 ATA/ATD、SOF 事实、装卸时间定稿、索赔了结、发票签发、加油交付、TCE 对比；缺项可直接生成跟进任务。
  6. 完成航次时系统发出 voyage.completed 事件，自动收缩日程、生成缺项任务与 TCE 快照。

船队孪生

  1. 打开 /twin 查看船队态势；可运行 what-if 推演（演示级）。

系统同步追踪 EU ETS 碳排放与 CII 评级，碳成本可按航次自动分摊。

5. 装卸时间、索赔与财务

Laytime 与滞期索赔

  1. 滞期或财务角色进入 /finance。
  2. 创建装卸时间单：关联航次 / 挂靠港，录入允许时间、周转时间、滞期费率与时间段（含除外时间）。
  3. 计算 → 定稿后，可发起 demurrage 索赔并流转谈判 / 结清。

条款库：系统预置 10 套标准租约条款模板（SHINC、SHEX、WWD、WWDSHEX 等），可保存租家定制条款；计算时参数自动填入。

计算书可直接打印为 PDF（含公司抬头），支持批量导出 Excel。

港口使费、燃油、发票

  1. 港口使费：PDA 编制 → 提交 → 批准 → FDA（记录差异）。
  2. 燃油订单：询价 → 下单 → 交付，校验 ROB 守恒。
  3. 运费发票：草稿 → 待批 → 开立 → 分次收款至 paid → GL 过账辅助。
  4. 发票签发、PDA 关闭会发出域事件，自动生成对账 / 过账任务（GL 过账失败时降级为任务，不静默）。
  5. 查看动态航次损益（估算 vs 实际 vs 差异）与 AR 账龄。

分析报表入口：/analytics

6. AI 与自动化（贯穿前 5 节的日常台面）

AI 与自动化不是独立的旁路模块，而是挂在原有链路的两端： 读入端——邮件、聊天记录、页面上下文由 AI 解析并起草； 产出端——业务节点发出域事件，流程把「下一步该谁做什么」物化成任务与通知。 贯穿全链路的约束是：AI 只起草、流程只物化，落库一律人工确认（例行任务中枢的四眼规则）。

AI 助手（任意页面 Ctrl+J）

  1. 在任意页面按 Ctrl+J 打开助手面板，可问「这票航次的 TCE 是多少」「哪些发票逾期未收」。
  2. 回答取自当前登录租户的数据与知识库；未配置大模型时回落内置规则引擎，回答角标标 rules，不会伪装成 AI。
  3. 助手可给建议动作与字段建议，但不会直接改台账——需回到页面确认后保存。

MariAI 对话（/ai/chat）

  1. 打开 /ai/chat，选择 Agent（估算 / 航次 / 市场等）并新建会话。
  2. Agent 可调用只读工具查询租户数据；消息里的「工具调用」可展开看到实际执行的查询，便于核对口径。
  3. 会话支持重命名、归档、删除（进回收站）；未配置模型时页面顶部常驻提示，已配置但回落时在回复下方说明。

AI Hub（/settings/ai）

  1. 租户管理员在 /settings/ai 配置模型服务商与模型，可做连通性测试，并设置默认参数。
  2. 查看用量与配额；也可自带密钥（BYO key），自带密钥的调用不计入平台额度。
  3. 把技能绑定到模块、配置 Agent 与技能目录；计量默认关闭，需要统计时再开。

邮件复核与 AI 落地（/email/review）

  1. 在 /email/review 同步邮件：可设 7 / 14 / 30 天窗口与条数上限，按收件箱 / 已发送等文件夹分页浏览。
  2. 系统按业务类型分类并抽取字段（船舶、港口、运价、装卸时间等），正文已转纯文本，解析字段带来源与置信度。
  3. 逐类执行：成交回顾 → 生成估算与租约草稿、港口使费 → PDA 草稿、发票 → 发票草稿；也可确认解析结果、忽略并记住该发件人、归档到业务单据。
  4. 草稿在「待确认草稿」中人工复核后才落库；详情里还能「填入航次计算」，把邮件解析结果带进估算页。

航次计算 AI 填充（三处入口）

  1. 估算页 /estimates、邮件详情、航次工作台均可「从文本填充」。
  2. 粘贴邮件 / 聊天记录 → 解析 → 逐字段卡片（值、来源 llm 或 rules、置信度），可勾选、可改值。
  3. 「应用到表单」后写入估算表单（船舶、对手方、货名、装卸港、运价等），保存前仍需人工复核。

例行任务中枢（/routine）

  1. /routine 三个 Tab：待确认草稿 / 例行任务 / 技能模板。
  2. 草稿的每个字段都带证据出处；四眼规则要求第二位确认人复核后才写回业务表（与发起人同人则不放行）。
  3. 例行任务可定义触发条件（事件 / 时间窗）、执行动作与分派角色，可手工新增、编辑、删除与立即运行；技能模板定义可复用的动作集。

域事件自动化与航次收尾

  1. 业务节点自动发出域事件：航次完成、lifting 固定 / 完成、租约修订、发票签发、PDA 关闭、加油交付、索赔和解、NOR 更新、装卸时间草稿。
  2. 处理器把事件物化为跟进任务 + 站内通知 + GL 过账尝试；处理器异常只留痕、不回滚业务操作（自动化失败不挡住业务）。
  3. 完成航次前看收尾清单（航次工作台 → Closeout）：挂靠港 ATA/ATD、SOF 装卸事实、装卸时间定稿、索赔了结、发票签发、加油交付、TCE 对比；缺项按角色与时限自动生成任务。
  4. 审批链在 /workflows/inbox 处理；审批节点定义在「系统设置 → 工作流」。

文档与 PDF

  1. 内置 14 类单据模板：发票、贷记通知单、装卸时间计算书、租金账单、成交回顾、估算报价单、PDA、索赔函、SOF、包运合同、航次指令、对账单、汇款通知、供油报告。
  2. 模板带公司抬头，可在 /settings/templates 定制与预览；业务单据上「Export PDF」直接导出，计算书含抬头可打印。
  3. 渲染记录可在文档中心查询，并可从站内发送。

10. 边界说明与落地建议

  • 适合： 流程培训、售前演示、中小团队试点台面、与现有系统并行验证。
  • 慎用为唯一生产核心，直至： ERP 过账、船期可视化冲突策略、关键连接器与审计合规达到贵司验收标准。
  • 租户独立库可登记绑定，当前业务会话默认仍走主库；云厂商「一键部署」多为模板指引。
  • AI 的边界： 未配置模型时问答与抽取回落内置规则引擎（回复角标标 rules）；AI 只起草、不直接写台账，草稿需在「待确认草稿」经人工复核（四眼规则）后才落库；自带密钥（BYO key）的调用不计入平台额度。
  • 自动化的边界： 域事件只产生待办与通知，不推进状态机、不代替审批；任务可由人手工改、删、提前触发，覆盖自动化结果。
  • 应用内知识中心兼有检索增强 FAQ 与大模型问答两条路径，回答口径以来源栏目与引用为准。
